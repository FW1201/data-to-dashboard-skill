# Deployment and acceptance

Use this sequence as an evidence ledger; adapt implementation to the folder's schema.

1. **Local reference:** record file paths, SHA-256, headers, nonblank row counts, unique key counts, known bad rows, metrics for at least two meaningful filters, and expected latest period. Keep detailed source data in the private project workspace.
2. **Identity and backup:** verify the supplied editor URL's Script ID, remote project contents, spreadsheet ID, and existing deployment ID/access. Back up remote code before push.
3. **Implementation:** keep parsing/aggregation separate from Google UI code. Validate dates, numeric units, statuses, and uniqueness; use null/“not provided” for incomplete metrics. Build data table, metric cards, filter controls, and relevant charts with readable mobile layout. Keep generated sheet rebuild idempotent and preserve user source tabs.
4. **Refresh:** install named triggers only once. Verify edits cause recomputation, scheduled checks serve external modifications, and the web app retrieves fresh data. State that Google time triggers are approximate and browser polling only updates an open page.
5. **Deploy:** sync to the verified Script ID, execute setup, inspect execution logs, create or update version/deployment with the intended viewer access. A development `/dev` URL is not the final deliverable.
6. **Remote reconciliation:** read source sheet row counts/headers and compare with local; inspect generated dashboard sheet/chart count; open `/exec`, wait for the actual data state, and compare visible values for default and alternate filter states. Ensure displayed links point to the intended spreadsheet.
7. **Mutation round-trip:** before editing, record the source tab, A1 range, stable row key, original value, expected delta, and restoration value. Use a precise range/API update where available; avoid free-form typing in a spreadsheet UI after a tab switch, which can overwrite an unrelated cell. Wait or refresh, confirm the exact expected delta in sheet and web app, restore the original value, and verify original totals return. API updates may not invoke an Apps Script `onEdit` trigger, so invoke the scheduled refresh or rebuild function when required. Finish by comparing every authoritative source table with the local reference again. Avoid permanent edits or duplicate IDs. Test a missing/invalid-value case locally, and remotely when safe.
8. **Handoff:** provide working `/exec` URL, source spreadsheet URL, refresh interval/trigger behavior, reconciliation results, and unresolved caveats. If any step fails, label the result as pending and provide the repair action; never turn a partial check into a pass.

Public release after a user-requested successful trial: create a new repository only after acceptance, stage an explicit allowlist of generic `SKILL.md`, references, scanner/tests, and a short repository README if useful. Exclude case-specific data, credentials, logs, and IDs. Check the public GitHub files after push.
